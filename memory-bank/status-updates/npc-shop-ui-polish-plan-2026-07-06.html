PRE-IMPLEMENTATION PLAN · 2026-07-06

NPC Shop UI Polish + Asset Backfill

Maintainer feedback on the live Shop tab: many items and shops have no icons, icon sizes are inconsistent (tiny vs normal), the stock area wastes vertical space, the services section blends into the transaction panel, and the tab force-opens a default shop instead of letting you browse the list. This plan covers a full asset backfill plus five frontend fixes — all inside the existing backend contract.

Workstreams

P1 · ASSETS

Backfill every visible shop item sprite

New tools/fetch_shop_assets.py derives its manifest from SHOP_DATA (all visible live/locked stock items whose registry entry has no existing asset), fetches through the shared rate-limited wiki client into shopitems/, and records provenance. SHOP_ITEM_IMAGES already existence-scans that folder, so new sprites wire themselves. Shop selector icons derive from the first stock icon, so the 50 iconless shops fill in for free. Unresolvable titles degrade to text-only (existing guard) and get reported.

tools/fetch_shop_assets.pyshopitems/assets_provenance.json
P1 · ICON SCALING

Nearest-neighbor upscale to uniform sizes

Wiki sprites vary from ~12px to ~40px; QIcon never upscales, so small sprites render tiny next to normal ones. A shared pixel-art icon helper will load the pixmap and scale it to the slot size with Qt.TransformationMode.FastTransformation (nearest neighbor — crisp pixels, no blur), applied to stock tiles, the shop selector, search rows, sell rows, and service rows so every icon lands at the same visual size.

ui.py
P2 · BROWSE-FIRST NAVIGATION

No default shop; click to open; collapsible detail

The Shop tab opens with only the search bar and the full-height shop list — no shop pre-selected. Clicking a shop opens the detail panel; a collapse control (and re-clicking the selected shop) closes it again so the list gets its space back. The list shows more shops at once because the detail panel no longer reserves its height while unused.

P2 · LAYOUT + SERVICES

Taller stock grid; services get their own framed section

The stock scroller grows from one cramped 78px row to a 2–3 row area that expands with the dialog, so a 29-item general store doesn't hide 80% of its stock behind a scrollbar. The Services / Vendor Actions block becomes a visually separate framed group — its own header, border, and inline qty + Use controls — instead of floating between the transaction panel and history. Tile sizes and section spacing get one consistent rhythm; all colors stay palette-derived per the dark-mode text rule.

Execution order

  1. Write tools/fetch_shop_assets.py (manifest from SHOP_DATA, dose/pack title overrides where needed) and start the ~570-item fetch in the background.
  2. Add the nearest-neighbor icon helper in ui.py and route all five shop icon call sites through it.
  3. Rework Shop-tab navigation: empty initial selection, detail panel hidden until click, collapse toggle, selector stretches when detail is closed.
  4. Raise the stock grid height and reframe Services / Vendor Actions as a separate group with its own header and controls.
  5. Update Qt tests: replace the default-shop test with browse-first assertions (no selection on open, click opens detail, collapse hides it); adjust existing shop tests to click a shop before interacting.
  6. Wire fetched sprites (registry existence-scan), re-run icon coverage checks, both full suites, and offscreen light + dark screenshots.
  7. Results artifact + memory-bank updates + commit to codex/npc-shop-frontend.
Contract boundary (unchanged): Qt still renders backend truth only — no prices, lock reasons, stock behavior, sell policy, or service semantics are computed in the frontend. Everything here is presentation: assets, scaling, layout, and navigation state.
