⚠ The architectural divergence to own

The designed pack is a real arrangeable set of 28 item slots (decision 3 + 5): you place inputs, they're consumed, and the bank run refills that layout. What shipped is a churn scalar — a per-target counter that adds max(gained, consumed) slots per action and forces a bank run at 28. It reproduces the teeth, but there is no arranged loadout underneath it, so advanced mode has nothing to arrange.

Reconciliation: keep the churn meter as the casual engine (it's fine — it's auto), and add a real per-target arranged pack for advanced mode that drives consumption and refill from the layout you set. That's the missing chunk, not a UI skin over what exists.

The eight core decisions (unchanged, for reference)

  1. Teeth for everyone. The 28-slot limit is real; bank runs cost reviews. A bag is worth exactly a bank run.
  2. Overlay, not replacement. Flat bank stays the source of truth; the 28 slots are a capacity+ordering layer over it. Bank is infinite.
  3. Shared execution, swappable policy. Bank runs always auto-execute. Casual = preset dropdown; advanced = arrange the 4×7 once, auto-executed.
  4. Advanced yields more — but a small ~10–20% edge, never a 2× gulf that punishes casuals.
  5. Input + output teeth, unified. The same 28 slots are drawn from (food/inputs) and deposited to (gathered/loot).
  6. Stackable = one slot; bags pack an unstackable material into one slot — the entire reason bags exist.
  7. Every bank run costs a review (combat 2, skilling 1). Drop = never bank = fastest XP.
  8. Keep/Drop per gathering target. Keep banks the product; Drop bypasses the pack for max XP/action.

Plus: held-item requirements resolve against the mode (advanced: the mould must sit in your 28 slots; casual: "owned in bank" suffices — toolbelt absorbs belt-able tools). Death drops the pack into the grave. Undo rolls it back. Coins → Money pouch (0 slots). Quest items abstracted. Per-target loadout persistence.
