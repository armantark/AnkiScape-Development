Attack types — stab, slash & crush

You noticed the attack-style selector says “Aggressive” but never which physical attack it is. The catch: the attack type isn't a property of the style — it comes from the weapon plus which slot you pick. A mace’s Aggressive is crush; a dagger’s Aggressive is stab; an axe’s third slot is crush even though its others are slash. So “Aggressive” genuinely can’t name a type on its own. This plan wires the real per-weapon table in and surfaces the type. Nothing here is built yet — this is for sign-off.

What’s true today

🎯
The style selector shows four fixed melee styles
Accurate / Aggressive / Defensive / Controlled, identical for every weapon. COMBAT_ATTACK_STYLE_DATA (combat_data.py:81) stores display_name, combat_class, xp_mode — but no attack type.
🧮
The damage formula ignores attack type entirely
Melee accuracy uses max(attack_stab, attack_slash, attack_crush) (logic_pure.py:1518) against the enemy’s max(defence_*) (logic_pure.py:1530). A parity shortcut — so stab/slash/crush is currently invisible and mathematically inert.
🗂️
The authoritative key already exists in the source data
Every weapon’s equipment block in items.yml carries weapon_type (Bronze dagger → weapon_type: 5 = DAGGER). Our generator currently derives only a coarse equipment_type string and leaves 84 weapons (Dragon dagger, Black 2h sword, Dragon scimitar…) in a generic "weapon" bucket. weapon_type resolves all of them authoritatively.

The parity model (AttackStyleData.kt)

2011Scape resolves the type with WeaponCombatData.getAttackStyleType(weaponType, combatStyle): find the weapon-type row, then read the style slot. The type depends on both. Same “slot”, different weapon, different type:

Weapon typeSlot 1 (Accurate)Slot 2 (Aggressive)Slot 3Slot 4 (Defensive)
Dagger stab Att stab Str slash Str stab Def
Longsword slash Att slash Str stab Shared slash Def
Mace crush Att crush Str stab Shared crush Def
Battleaxe slash Att slash Str crush Str slash Def
Spear stab Shared slash Shared crush Shared stab Def
Unarmed / typeless crush Att crush Str — crush Def

Proposed build

  1. Capture weapon_type in the generator.
    Add weapon_type: int to EquipmentItem and read it from the items.yml equipment block in tools/generate_equipment_data.py; regenerate equipment_data.py. Non-weapons / typeless → -1.
  2. Port the parity table into combat_data.py.
    A WEAPON_TYPE_STYLES map: weapon_type id → ordered list of (weapon_style, style_type, xp_mode) rows, transcribed verbatim from AttackStyleData.kt with a cite-and-pin source line. UNARMED covers -1 / fists.
  3. Resolver + selection.
    Given the equipped weapon, return its available style rows; the player’s current_combat_style indexes into them. Replaces the fixed four-style assumption for melee.
  4. Formula uses the resolved type Decision D1
    Melee accuracy reads the specific attack_<type> vs the enemy’s matching defence_<type>, replacing the two max() calls (logic_pure.py:1518 / 1530). XP mode is unchanged.
  5. Surface the type in the selector Decision D2
    Each style label gains its attack-type chip (stab/slash/crush), driven by the equipped weapon.

Heads-up: D1 changes live combat numbers. Against enemies whose per-type defences differ, choosing the type they’re weak to will hit more often than today’s max() (which always used their strongest defence). That’s the correct RuneScape behavior, but it is a real balance shift — flagging it so it’s a deliberate choice.
