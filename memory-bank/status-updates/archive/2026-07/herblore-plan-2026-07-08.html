Herblore — turning the “live-but-inert” potions into a real skill

The combat stat potions already exist as items and already drink correctly (potion_data.py, shipped 2026-07-07), but nothing sources them — its own docstring calls Herblore “a separate future skill”. This plan wires that skill: a review-paced, parity-transcribed three-stage pipeline (clean → unfinished → finished), built the same way Runecrafting and Cooking were. Nothing here is built yet — this is for sign-off. The knobs below are the decisions I need from you before I touch code.

Parity source HerbData.kt · mixing/PotionData.kt · 3 action files Template Runecrafting (grouped conversion skill) Risk Medium — new skill, many touch-points, no combat math

Decisions I need from you

A · How much of the potion tree do we build?
Runecrafting and Cooking were each transcribed to full parity from their source table. But Herblore’s table (mixing/PotionData.kt) has ~90 recipes, and most of them need herbs/secondaries with no source in AnkiScape (Juju vines want a Farming habitat; Dungeoneering herbs want Daemonheim). Pick the coverage:
Combat spine only
Just the 9 families above + their herbs/secondaries.
Smallest. Directly satisfies “source potions.” Herblore caps out low (~lvl 76). Feels like a stub.
Full standard tree REC
All ~30 mainline recipes (Attack→Prayer renewal, lvl 3–94) + 17 standard herbs.
A real 1–99 skill, matching how every other skill shipped. Inert products (energy, restore, prayer…) are valid parity items — same “live-but-inert” stance as the combat potions before this.
Everything
Standard + Barbarian mixes + Juju + Dungeoneering (~90).
Maximum parity, but most rows are permanently locked (no ingredient source), so the menu fills with dead entries. Not recommended until Farming/Dung exist.
B · Where do the raw inputs come from?
Grimy herbs, Vials of water, and secondary ingredients need an entry point into the economy. The bundle I recommend keeps it authentic where cheap and shop-simple everywhere else:
Drops + shop bundle REC
Grimy herbs drop from combat monsters (authentic); Vials of water & secondaries sold in a Herblore/general shop.
Uses the existing shop + combat-loot systems. Herbs feel earned; consumables don’t need a dead “fill vial” micro-step.
Shop-only
Everything (grimy herbs included) bought from a shop.
Simplest to build; least authentic. No combat drop-table edits.
C · Menu shape
Runecrafting groups its targets (Standard / Combination / Tiara / Hood). Herblore has three natural stages.
Three groups REC
Clean herbs · Mix unfinished · Mix potions — each a pickable target list, mirroring Runecrafting.
Flat list
One long list of every action. Simpler code, busier menu.
Parity is fixed, not a knob. Cleaning XP, the zero-XP unfinished step, finished-recipe XP, and every level gate are transcribed verbatim from the cited source with line pins — no invented clamps, no rebalancing. The knobs above only choose coverage and economy plumbing, never the numbers.

Build phases

  1. Data module + registry flip. Transcribe herblore_data.py from the pinned source; move the skill to CURRENT_SKILLS; wire constants.py. Prove items register & storage seeds.
  2. Pure conversion engine. apply_herblore_action_pure + lock reasons, with unit tests covering all three stages incl. the zero-XP unf step and level gates.
  3. Runtime + menu. handle_herblore_answer, can-start gate, target rows, UI group + icon. Herblore becomes a selectable review skill.
  4. Economy plumbing. Per knob B: shop stock + (optional) grimy-herb drops. Confirms the pipeline is reachable end-to-end from a fresh save.
  5. Verify + artifacts. Full offscreen suite green; live Anki smoke via Pinchtab; results artifact + memory update.
Each phase is a checkpoint commit to main (solo project). No push unless you ask.

Tests I’ll add

  • Pure: clean grants exact herb XP; unf grants zero XP and consumes clean+vial; finished grants exact recipe XP and consumes unf+secondary; each stage’s level gate blocks below-requirement.
  • Storage: fresh save seeds herblore_level=1 / herblore_exp=0 / current_herblore; migration backfills an old save with no regressions.
  • Integration: a review answer on a selected Herblore target advances the pipeline, awards XP, and respects the multiplier — same harness as the runecrafting review test.
  • Registry contract: every herb / unf / secondary / product name resolves in the item registry with an icon (the row-icon contract that bit the Stronghold work).
  • Manual: Pinchtab pass in live Anki — pick a Herblore target, answer cards, watch clean→unf→finished flow and a drinkable combat potion come out the end.
