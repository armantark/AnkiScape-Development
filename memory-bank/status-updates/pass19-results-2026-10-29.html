Held. Adding an entry starts the queue at once, in place of what runs.

The queue waited until the action you started by hand stopped, and a pickup never stops by itself. Now an add starts the queue unless it already runs, and the "Starts when … stops." line and "Start now" are gone.

Should an add to a paused queue start it again?

Stop pauses the queue. In this build, an add to a paused queue starts it again from entry 1. The other choice adds the entry and leaves the queue paused until you press Resume queue.

The queue runs only when its first entry is the action that runs.

A Start by hand pauses the queue only at the next card, so the add compares the running action with entry 1.

An add that cannot start says so, and your action continues.

The review found that this add reported success with no warning. The question about leaving a minigame session now also comes only for an add the queue takes.

Held. The Quests tab keeps its sort, tickboxes and filters between menus.

Anki's profile keeps the sort, both tickboxes and the Access, Difficulty, Length and Timeline lists, as it keeps the queue box's fold.

Should the search text be kept too?

The search box empties when the menu closes. Kept text can hide quests the next time you open the tab.

One function shows the saved view and saves each change.

Changed. Each quest name shows its progress in a softened game colour.

The first build used the game's pure colours, which you said glare. These keep the hues at a lower saturation, and each reads at a contrast of 4.2:1 or more.

Which quest is cyan?

"Selected/current" can mean two quests. In this build, cyan marks the quest that runs now. The other choice also marks the quest you picked last while another skill runs.

Light mode uses darker shades, because yellow and cyan vanish on white.

Should the status text take the colour too?

Only the name is coloured, as in the game's quest list. The status text after it ("Stage 1/5", "Not started") stays grey.
