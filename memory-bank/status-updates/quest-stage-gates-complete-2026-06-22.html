Complete slice - 2026-06-22

Quest stage gates are real now, with The Knight's Sword as the proof case.

The old start-only quest model now has a stage-aware blocker layer. The player can start a quest when start requirements are met, but cannot advance the current stage until the source-backed stage requirements are satisfied.

396 Unit/integration tests passed through python3 run_tests.py.
396 Qt/offscreen tests passed through the .venv-qt discover run.
1 Quest fully proven with source-backed stage requirements; catalog-wide parity remains explicit backlog.

Backend Landed

Structured stage requirements QuestStageRequirement covers required inventory, consumed inventory, tools, required actions, route flags, and combat encounters.
Progress gate can_progress_quest_pure() separates startability from finishability and powers runtime readiness checks.
Stage-local consumption apply_quest_progress_pure() now refuses blocked stages and consumes stage items only when the stage advances.
Reward safety Quest points, item rewards, and XP rewards still fire once, and only after legitimate final-stage completion.

Frontend Landed

New visible state The Quests tab can show Blocked: Needs Redberry pie x1 for a started quest.
Filters preserved Hide unable to start still hides only true start locks, so in-progress blocked quests stay visible.
Up-front requirements The Knight's Sword lists Mining 10 plus the items used later in the quest before the player starts.
Compact player wording Blocker reasons name the missing item, tool, action, route, or combat encounter without internal implementation terms.
