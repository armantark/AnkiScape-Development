PRE-IMPLEMENTATION PLAN · 2026-07-07

Shop Access Gates + Wilderness Ambush

Owner-grilled hybrid (2026-07-07): every shop classified in an access ledger; gates implemented only where real walls exist; Wilderness shopping carries a declared, kill-capable ambush risk.

  1. Access classification — hand-audited SHOP_ACCESS_RULES in the generator (shop_id → quest / route-stage / guild-skill / wilderness / open, each with a source note), emitted onto shop rows and into the coverage ledger. Uncertainty defaults open, recorded.
  2. Runtime locks — shop_logic evaluates access against the save at view/preview/apply time (quest gates use the existing quest-state shapes; guild gates check the skill level), producing a dynamic lock_reason ("Requires Lost City", "Requires 68 Fishing") rendered through the existing visible-locked surface. Buys and sells both deny while locked.
  3. Wilderness ambush — persistent wilderness_shop_slots accumulator; each purchase adds slots (stackables one per type, unstackables one per item); every completed 28-slot block rolls 1%; on trigger, one PKer-style hit via the real combat damage roll (declared max 250 LP, engine 1..max−1 semantics) lands on combat_lifepoints; death routes through the normal grave path. Damage/death state rides the purchase's shop event for rollback. Qt shows the dangerous-action confirmation on Wilderness purchases (session-scoped) and a Wilderness flag in the shop header.
  4. Tests (gate evaluation per class, ambush slot math, kill path, rollback), access-ledger audit doc, results artifact, both suites, commit per convention.
Declared inventions: the ambush formula (1% per 28 slots, 250 LP max) and the review-model gate evaluation are AnkiScape adaptations — both get ledger rows. The gate list itself is source-auditable per shop (quest walls from the 2011 game's access requirements).
