Telemetry for every action, one shared review-odds adapter.

The mackerel/cod/bass row exposed a real observability gap: dry Fishing attempts were valid gameplay but left no saved trace. This slice adds per-action telemetry first, then routes probabilistic skills through the same AnkiScape normalization curve so the add-on feels consistent without copying harsh source tick odds directly.

Current Lv 18 big-net mackerel chance per action tick. One catch in 20 is unlucky but believable, and there is no telemetry today to prove it after the fact.

What changes

Each completed review action records attempts, successes, failures, expected successes, dry streaks, and produced outputs under one player-data telemetry key.

What stays source-backed

Mining, Woodcutting, Fishing, Firemaking, Cooking, and Hunter keep their audited source low/high or catch data. The new layer adapts those facts to Anki review cadence.

What stays out

This is not a full balancing UI. I will add durable backend summaries and targeted tests, then leave a clear frontend prompt if a richer stats screen should follow.

1. Normalize

Introduce one `normalize_review_success_probability_pure` function and have probabilistic skill helpers call it.

2. Record

Add pure telemetry helpers and record only real started actions, not level locks or missing-material blocks.

3. Verify

Unit-test the math and telemetry, then integration-test dry Fishing, productive failure, and deterministic success paths.

4. Document

Update Memory Bank patterns/progress and add a completion artifact with the before/after odds.

Backend contract

player_data["action_telemetry"] will be the durable store. It should be safe to inspect, migrate, undo, and summarize without special log parsing.
