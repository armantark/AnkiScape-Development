# Review: S1 (implemented) and S2 (proposed patch)

Static read-only review only. I have not run test lanes and have not seen offscreen captures; nothing below claims either passed.

## Decision

- **S2: Approve with two minor pre-landing tweaks**; HUD fit must be confirmed by the pending viewport captures.

## S1 — Confirmed defects

**1. Action change does not end the Encounter (contract violation).**
The contract ends the Encounter on "Action or target change" and separately keeps finisher selection *within* the Combat Action. S1 clears `combat_encounter` on target change (`_set_combat_target`), skill/activity change (`commit_direct_action`, `save_skill`, both utility-selection sites), bankstanding (`_switch_to_bankstanding`, `_on_main_menu`), and bank runs (`request_combat_bank_run_now_pure`, `_combat_progress_or_start_bank_run`). No supplied path clears it when `combat_action` changes via the Action combo (`on_set_combat_action` → method-values/`reconcile_combat_method_pure`), which now applies the change and preserves the encounter.
*Trigger:* mid-Encounter, switch Action in the combat menu → new Action takes effect next review against stale enemy LP/countdowns.
*Correction:* mirror `_set_combat_target` — when the persisted `combat_action` actually differs, commit `combat_encounter: {}` in the same values; ensure finisher selection does not trip that clear. If the real handler (not in the supplied source) already clears, disregard.

**2. Silenced residual refusals / unconditional save.**
- `on_set_combat_pack_mode` now ignores `_ok`/`_reason` and always calls `_save_combat_state_update(new_data, …)`. If `set_combat_pack_mode_pure → reconcile_combat_method_pure → unload_combat_supply_loadout_pure` can still return `ok=False` for any non-encounter reason, this persists a partially reconciled loadout and reports success.
- `_set_combat_method_values` fails silently, and ui.py removed the combo revert-on-`False` for action/style/spell/pack pickers; `on_equip_item`/`on_unequip_slot` ignore reconcile's `ok` and fall back to a possibly wrong message.

The contract forbids enemy-alive refusals only. *Correction:* either gate the save on `ok` and restore error surfacing/revert for remaining failure modes, or state in code that these paths are now infallible (unload cannot fail once the encounter guard is gone).
