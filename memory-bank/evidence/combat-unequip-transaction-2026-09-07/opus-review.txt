## Findings

1. The frozen baseline exec depends on a deprecated import fallback. `tools/combat/compare_enemy_unequip_transaction.py:373-374` executes the baseline in a bare `types.ModuleType`. The baseline engine uses level-2 relative imports (`logic_pure/logic_pure_combat_engine.py:5-16`). A bare module has `__package__ = None` and `__spec__ = None`, so CPython falls back to `__name__` and emits an `ImportWarning`. The handoff commands still work. A host with `-W error` or dev mode fails. One line fixes it: set `baseline.__package__ = "ankiscape.logic_pure"` before the exec.

2. The guard writes the import-block policy twice. `tools/combat/check_enemy_unequip_guards.py:33-42` installs an in-process audit hook, and lines 126-129 embed the same rule again as a subprocess bootstrap string. Smaller replacement: run all seven cases through the existing bootstrap subprocess. That deletes the in-process hook, `runpy`, `contextlib`, `io`, and `unittest.mock.patch`, and it gives stronger isolation.

3. The random-generator state evidence is vacuous here. `RecordedRandom` returns the fixed prefix for the first 100 draws and never calls the parent generator (`tools/combat/compare_kill_rewards.py:30-34`). The bursts use 1, 4, and 6 ticks, so no run reaches draw 100, and `snapshot()[0]` is the seed state in every step of every case. The handoff claims the comparison records "random-generator state". The real evidence is the draw count and the constant values. Full return-value equality remains the strong proof, so do not read the state field as independent evidence.

4. `bank_delta` and `pack_delta` are absolute counts, not deltas (`tools/combat/compare_enemy_unequip_transaction.py:355-361`). The fixtures start at zero, so the value equals the delta by accident. A future fixture with a nonzero start would let a wrong engine pass the route check by setting the count instead of adding to it. The baseline equality check covers this risk today.

5. One assertion message is wrong. `tools/combat/compare_enemy_unequip_transaction.py:341` asserts `rng.draws` with the message "The enemy attack selector did not consume RNG." A non-empty draw list proves only that some consumer drew a value; the player attack and the ambush roll also draw.

6. The output file is rewritten once per case (`tools/combat/compare_enemy_unequip_transaction.py:410`). Each write re-encodes every base64 pickle. Four cases make this harmless, but the write belongs after the loop.
