## Verdict

I found no blocker in the visible code. On the visible code, these constraints are met:
- **Trim tool:** it checks every target before any file change.
- **Remote runner arguments:** focused mode requires both flags together and a positive count. It rejects empty selectors. Selectors are shell-quoted, and the mirror lock still covers the run.
- **Full-suite floor:** full mode still calls `validate_test_summary`.
- **Fetch skip:** it now returns before any network call.
- **Hunter paths:** all ten paths are the same as before.

Several findings below are medium only on a condition that the packet cannot prove.

## Actionable findings

1. **Medium (conditional): `tools/run_remote_tests.py`, `_stream_remote_run`.**
   - **Failure:** Focused runs and full runs use the same `run_id` pattern, `{lane}-{time}-{hex}`, in the same `reports/` directory. Suppose a program reads the latest `plain-*.report` as proof that the lane passed. A focused pass of 19 tests then looks like a full-lane pass, and a failing full-lane condition is accepted.
   - **Fix:** Add the scope to the name, for example `f"{lane}-focused-{...}"`, when `selectors` is not empty. If no program reads these reports, this finding does not apply.

2. **Medium (conditional): `tools/run_remote_tests.py`, `_remote_lane_command`, Qt branch.**
   - **Failure:** The full Qt lane runs `-m unittest discover tests`, but the focused Qt lane runs `run_tests.py --quiet --`. These are different test entry points. If `run_tests.py` installs plain-lane stubs or plain-lane path setup, a focused "qt" run does not test real Qt. The evidence says "19 on MacBook" but does not say which lane ran.
   - **Fix:** Confirm that `run_tests.py` under `REMOTE_VENV/bin/python` imports real `aqt`. If it does not, the Qt focused command must use `-m unittest` with the selectors, and both lanes must use one selector format.

3. **Medium (conditional): `tools/run_remote_tests.py`, `main`, the failure path.**
   - **Failure:** When a run fails, `main` saves a record of the unfinished run to `_pending_path()`, and the diff hides what that record contains. Two outcomes are possible:
     - If a focused failure saves only the lane name, a later retry runs the wrong scope.
     - If any success path deletes this record, a focused success can erase a record of a full-lane failure.
   - **Fix:** Store the selectors and the expected count in the record. A focused success must never delete a full-lane record.

4. **Medium (conditional): `tests/test_remote_test_host.py`, `test_focused_run_requires_exact_count_and_zero_skips_without_lowering_full_floor`.**
   - **Failure:** Output cases 2 to 4 go through the failure path in `main`, which writes the pending-run record. The test does not patch `_pending_path` or the mirror lock file. If `setUp` does not send both into the temporary directory, the test writes to the real record and the real lock.
   - **Fix:** Confirm that `setUp` redirects both. If it does not, patch both in this test.

5. **Medium (conditional): `tools/promotion/lane_execution.py`, `_run_gate_checks`.**
   - **Failure:** The lane output filter now keeps all output except the progress lines. Before, it kept only the last 20 or 30 lines. This is safe for display and evidence text. If any code decides pass or fail from the kept lines, for example by a search for an `OK` or `Ran` line, text that a passing test prints can now match. The old line limit reduced that risk.
   - **Fix:** Confirm that the lane result comes from the exit code and from a summary parse of the raw output. Also confirm that `plain_only` still has a use. If it has none, remove it.

6. **Medium (conditional): `core/constants_parts/skill_assets.py`, module digest.**
   - **Failure:** `HUNTER_SHARED_ITEM_IMAGES` has the same name and value, but it now enters the `skill_assets` namespace before `from .skill_catalog import *`. Before, it came after `HUNTER_ITEM_IMAGES`. The package `constants_parts` also gets a new submodule attribute, `hunter_assets`. If `tools/module_surface` hashes namespace order or lists submodules, the pinned digests change. This includes `QT_DIGEST_OVERRIDES`.
   - **Fix:** Run `test_first_wave_digests` on both interpreters. If a digest changes, move the import line to the old position, directly after `HUNTER_ITEM_IMAGES = {}`. This keeps one owner and the old insertion order.

7. **Low: `tools/fetch_hunter_assets.py`, module imports.**
   - **Failure:** The new import comes after the `sys.path` edit but has no `# noqa: E402`, unlike the next import, so lint reports it. The import also runs the `ankiscape.core` and `ankiscape.core.constants_parts` package `__init__` files, which the tool did not load before.
   - **Fix:** Add `# noqa: E402`. Confirm that the tool starts under plain Python without Anki installed. Root has not yet run the asset tests that import product code.

8. **Low: `tools/fetch_assets.py`, `fetch_asset`.**
   - **Failure:** The skip check changed from `exists()` to `is_file()`. If a directory is at the output path, the function now calls the wiki and fails later, at the write. The old code skipped that path with no network call.
   - **Fix:** Keep `output_path.exists()`.

9. **Low: `tools/fetch_assets.py`, users of `FetchOutcome`.**
   - **Failure:** Skipped outcomes now have `None` in `source_wiki`, `image_url` and `file_page_url`. Any code that formats, serializes or compares these fields for skipped rows now gets `None`. The per-skill fetchers changed, but they are outside the packet.
   - **Fix:** Search `tools/` for these three fields. Confirm that every user handles skipped rows and that no `None` value goes into a provenance file.

10. **Low: `tools/audit_test_quality.py`, `_import_module_name`.**
    - **Failure:** The audit reads a relative import in a package `__init__.py` as relative to the parent package. The code uses `current_module.split(".")[:-1]`, so `from .x import Y` in `tests/pkg/__init__.py` resolves to `tests.x`, not `tests.pkg.x`. If `tests.x.Y` exists and is a test class, the audit accepts ancestry that Python would not use. That is a fail-open result.
    - **Fix:** Record which index keys come from `__init__.py`, and keep the last name part for those keys.

11. **Low: `tools/audit_test_quality.py`, `imported_binding`, `ast.Import` branch.**
    - **Failure:** `import package.harness` without `as` binds the name `package`, but the code returns `("package.harness", "")`. The audit then looks up a base written as `package.X` in `package.harness`, which is the wrong module.
    - **Fix:** When `asname` is `None`, return the top-level module `alias.name.partition(".")[0]`.

12. **Low: `tools/audit_test_quality.py`, `_test_module_index`.**
    - **Failure:** The index parses every `*.py` file under the test root, not only test files. One fixture file with invalid syntax or non-UTF-8 bytes now stops the whole audit.
    - **Fix:** Parse a module only when resolution asks for it. The simplification pass below shows how.

13. **Information, to verify: the resolver now rejects some bases that the old code accepted.**
    - **Change:** It now rejects `x.TestCase` imported from an external module, and chains such as `unittest.case.TestCase`. This fails closed, as the constraints require.
    - **Effect:** Each such class in the real suite becomes a new `undiscovered_test_method` hard issue.
    - **Check:** Run the audit on the real `tests/` directory. Compare the hard issues with the base branch before landing.

## Simplification pass

- **`tools/run_remote_tests.py`, `_stream_remote_run`:** The conditional call `_remote_lane_command(lane, selectors=selectors) if selectors else _remote_lane_command(lane)` is unnecessary. The default is `()`, so both branches produce the same string. Replace it with `_remote_lane_command(lane, selectors=selectors)`, and update any test mock that takes one argument.
- **`tools/promotion/lane_execution.py`, `_run_gate_checks`:** Two lambdas call `_tail_without_progress(lines, len(lines))`. Replace them with one filter function, `_without_progress`, passed directly. Keep `_tail_without_progress` only if other code calls it.
- **`tools/audit_test_quality.py`, `_test_case_class_names`:** The function takes `tree, path, tests_root, modules` and computes the module name again, although `audit_test_suite` already has it. Replace the signature with `_test_case_class_names(module_name, modules)`.
- **`tools/audit_test_quality.py`, `_test_module_index`:** The index parses every file in advance. Replace it with a map from dotted name to `Path` and a cached parse on demand. This also removes finding 12.
- **`tools/audit_test_quality.py`, `imported_binding`, the `unittest` checks:**
  - **Why they are not needed:** The `node.module not in modules` and `alias.name not in modules` clauses guard against a local module named `unittest`. The test runner imports the real `unittest` before any test, so a root-level `tests/unittest.py` does not replace it at run time. Please confirm this for `run_tests.py`.
  - **A second problem:** The marker value `("unittest", ...)` uses the same key space as a local module named `unittest`.
  - **Replacement:** Remove the two clauses, and use a marker that cannot be a module name, such as `("<stdlib unittest>", "TestCase")`.
- **`tests/test_module_surface.py`, `test_digest_failures_report_each_module_and_interpreter`:** This test checks the standard library's `subTest` behavior, not project code. Remove it, and keep the `subTest` wrappers.
- **`tests/test_fetch_assets.py`, `test_hunter_manifest_leaves_shared_images_with_their_owning_fetcher`:** The three `assertNotIn` lines repeat what the `isdisjoint` check already covers. Remove them.
- **`tests/test_ui_asset_normalization.py`:** Both new tests define the same fake image backend. Replace the two copies with one module-level constant.
