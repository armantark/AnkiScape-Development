## How the fix works

The patch changes how the audit counts where a name gets bound in a module. The old code counted top-level statements. A `try` statement that held an import counted as one binding, and the audit could not follow it, so the real harness failed. The new code walks into control-flow blocks such as `try`, `if` and `for`. It returns each import, assignment or class definition that binds the name. It still requires exactly one binding, and it stops at class and function bodies (`tools/audit_test_quality.py:586-594`).

## The real caller

The name `MainMenuWidgetTest` has one binding in `test_target_level_order.py`: the import inside `try` at line 120. The other import in that `try` block (`from aqt.qt import Qt`) does not bind the name.

The audit resolves the import to `tests.test_main_menu_widget`. That module defines `class MainMenuWidgetTest(unittest.TestCase)` once, at top level, on line 608. The file has no star import and no other binding of the name, so the class resolves as a genuine test case.

Removing the extra `unittest.TestCase` base changes nothing at runtime. `MainMenuWidgetTest` is already a `TestCase`, and it is bound even when aqt (the Anki Qt package) is missing, because that module defines it unconditionally.

## Fail-closed cases

| Case | Result |
|---|---|
| Alternate import in the `except` handler | 2 bindings, so it fails |
| Assignment in the handler, or after the `try` | 2 bindings, so it fails |
| `del Base` | Counts as a binding, so it fails |
| Ordinary base (`ordinary.Base`) | Has no `TestCase` ancestry, so it fails |
| Unknown module | `_import_binding` returns `None`, so it fails |
| Cyclic import | The `resolving` guard returns `False`, as before; the existing test still covers it |
| `from x import *` near a real import | Now also counts when nested, so it is stricter |

The new walker never finds fewer bindings than the old code. Each old top-level match now gives at least one binding. The only case that newly passes is a single import or class definition inside control flow, which is the intended case.

## Bugs

1. **An `except ... as Name` rebinding fails open.** `ast.ExceptHandler.name` is a plain string, not a `Name` node, so `_module_binds_name` does not see it.
   - Trigger: `try: from harness import Base` then `except ImportError as Base: pass`.
   - Result: the audit sees one binding and accepts `Base`. At runtime the handler binds `Base` and then deletes it.
   - Location: `tools/audit_test_quality.py:574-583`.
   - Smallest fix: add one branch that returns `node.name == name` for `ast.ExceptHandler`. Also add one "handler alias" row to the new test.
2. **Match-statement captures fail open, with low impact.** `ast.MatchAs.name`, `ast.MatchStar.name` and `ast.MatchMapping.rest` are also plain strings. The same one-branch fix covers them if you want them.
3. **Expressions that a class or function definition runs in the module scope, with very low impact.** Python runs decorators, base classes and default arguments in the module scope. A walrus assignment there (for example `def f(x=(Base := object())): ...`) binds a module-level name. The walker skips it because it stops at the definition node. I rate this as a limit and would not fix it.

## Limits (no action needed)

- Comprehension variables and walrus assignments inside a `lambda` belong to their own scope, but the walker counts them. This can only reject a genuine name, never accept a bad one.
- The audit accepts a unique import inside `try` even when the import can fail. This is correct: if the import fails, the class statement raises `NameError` and the test module fails to load. The audit does not see that.
- The audit still scans only top-level classes of a test file for test methods (`class_names`). A test class inside an `if` block is not audited, as before.
