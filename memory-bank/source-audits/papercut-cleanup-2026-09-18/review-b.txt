I found one real bug and one minor one. The lease-return guards, the `recover_stale` flag and the inventory checker hold up against the behavior you described.

## Findings

**1. Medium: a branch name that starts with `refs/heads/` is checked one way and checked out another way.**
- **Location:** `tools/worktree_guard.py:167` and `tools/worktree_guard.py:212-226`.
- **Trigger:** Run `lease refs/heads/goal/x` when `goal/x` exists and is not checked out. The duplicate-branch check at line 167 strips the prefix, so it examines `refs/heads/goal/x` and finds it free. The existence check at line 218 does not strip it. It looks for `refs/heads/refs/heads/goal/x`, which is not there. The code then runs `checkout -b refs/heads/goal/x main`. That makes a new, confusingly named branch from `main` instead of checking out the existing `goal/x`. The lease output also reports the unstripped name. The test at `tests/promotion/test_worktree_release.py:193` shows that the prefixed form is meant to be accepted, but it only tests the refusal case.
- **Smallest fix:** Put `branch = branch.removeprefix("refs/heads/")` at the top of `lease_worktree`. Then remove the `removeprefix` call from `require_branch_available` so the name is stripped in one place only.

**2. Low: a gate marker that disappears during the check is reported as unreadable.**
- **Location:** `tools/worktree_guard.py:248-254`.
- **Trigger:** A gate finishes normally and deletes its marker file. This can happen after the directory listing and before the file read. Gate cleanup does not take the landing lock (`locking.py:51-55`), so holding that lock does not prevent it. The read then raises `FileNotFoundError`, which the code catches as an `OSError`. The return is refused with the message "unreadable promotion gate marker". This fails safely, but the message is wrong, and the operator must retry.
- **Smallest fix:** Add `except FileNotFoundError: continue` before the existing `except` clause.

## Checks that pass
- **Coordination:** `release_worktree` takes the landing lock with `recover_stale=False` before the marker check. It holds the lock through the dirty-work check, the lease check, the detach and the pool return, and it releases the lock in `finally`.
- **Lock waiting:** `open_locked_file` confirms that the file it locked is still the file at the lock path. So a process that waits for the lock cannot hold a lock file that the previous owner has already deleted.
- **No recovery or process kills during return:** With `recover_stale=False`, a lock held by another process is refused without reading its record or killing a process. The return path never calls `active_gate_records`, which is the function that deletes stale markers and kills processes.
- **Gate markers:**
  - A marker for this worktree is refused whether it is old or new, and whether it is locked or not.
  - A marker directory that cannot be listed is refused. A missing directory is accepted, and a dangling directory link is refused.
  - A marker with bad content or a relative worktree path is refused.
- **Lease identity:** A return is refused for an empty lease ID, zero or duplicate matching rows, a status other than `leased`, a different lease ID, a relative path, or status output that cannot be read. The `--if-lease-id` flag also guards the actual return.
- **Branch check timing:** The duplicate-branch check runs before `treehouse get`. Git also refuses to check out a branch that another worktree already has, which covers a race between two leases.
- **Status command:** `status` passes the pinned `--root` and `--json` through to treehouse and changes nothing.
- **Inventory checker:**
  - It computes each source's SHA-256 hash from the raw bytes stored at the baseline commit (the compressed bytes for `.gz` sources).
  - It reports missing, extra and repeated incident lines, groups that name an unknown source, and duplicate group IDs.
  - It exits with a failure code when it finds any error.

## Simplification
- In the inventory checker, the `repeated` test `count != 1` can only be true for counts above 1. `count > 1` says the same thing more directly.
- No other part of the reviewed code has extra layers to remove.
