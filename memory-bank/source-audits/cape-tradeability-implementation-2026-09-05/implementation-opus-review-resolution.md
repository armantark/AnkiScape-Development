# Implementation review resolution

The retained `implementation-opus-review.txt` accepts the product diff and the two authorized count updates. The review was text-only and did not inspect the full evidence packet. The following decisions combine that review with local source inspection and the retained historical MacBook focus run.

| Finding | Disposition and evidence |
| --- | --- |
| F1, missing snapshot | Rejected. `owner-snapshot.json` is durable candidate evidence, bound in the implementation manifest and included in the intended commit. The compact review packet's four-file code-hash list did not enumerate every candidate evidence file. No source fixture is removed or relocated. |
| F2, missing coverage assertion | Accepted. Before the loop, the test now asserts that the snapshot's exact storage-key set equals the two cape names. |
| F3, dependent sell step | Rejected. The sequence deliberately tests buy, fill, collect, sell, fill, and collect. Seeding a replacement item would hide failure to obtain the bought cape. The historical downstream failures are recorded as cascades, not independent product failures. |
| F4, real Collection with runtime fakes | No concrete defect found. `tests/test_integration_smoke.py:43–77` replaces `aqt`, `aqt.qt`, `aqt.reviewer`, and `anki.hooks`; it does not replace `anki` or `anki.collection`. `tests/test_storage_runtime.py:14` retains the real Collection class before fixture setup. The historical Qt real-Collection test constructed the collection, placed and saved an offer, and reached the inventory comparison after real config reload. Its first failure was the same fixture normalization mismatch. Each test restores `sys.modules` with its registered cleanup. No fixture import change is warranted by this evidence; the revised full lifecycle still requires execution. |
| F5, module-scope alchemy import | Rejected. Static inspection of `runtime_actions_magic.py`, `runtime_actions_context.py`, and `runtime_actions_shared.py` found no `aqt` or `anki` imports. The historical plain and Qt lanes both imported the module and passed the actual shop/alchemy consumer test. Replacing the real value-map builder with catalog-derived values would remove useful consumer coverage. |
| F6, store-specific sell fraction | Rejected. `logic/shop_logic.py:999–1000` resolves sale price through `_sell_price_for_item`, and `:1614–1618` reads `SHOP_PLAYER_SELL_PRICES` by item name, without a shop parameter. The result is an item price, not a store-selected multiplier. The existing fixture chooses a visible general store, consistent with the existing shop tests. |
| F7, unchecked order index | Accepted. The test now asserts exactly one order before its initial index operation. |
| F8, asset and provenance guards | Rejected. Preserved asset identity and exclusion of `buy_limit` from price provenance are explicit requirements of this two-cape contract. Both checks are limited to these capes. |
| F9, unchanged values in test name | Rejected with this clarification: eligibility is newly enabled, while the numeric source values already existed. Baseline `SHOP_PLAYER_BUY_PRICES` contains `400`/`800`, and `SHOP_PLAYER_SELL_PRICES` contains `120`/`240`. `_magic_alch_values` reads the existing buy-price table; these consumers do not derive their values from newly added GE guide prices. |
| F10, literal arithmetic expectations | Optional and declined. The fractions remain concise checks of the unchanged value contract; the test also checks actual coin outputs. The historical consumer tests passed. No unrelated expectation rewrite is needed. |

The runtime fixture also receives the separately diagnosed two-line baseline save/reload before Coins and equipment are seeded. All existing assertions remain. The test moves into `tests/item_tradeability/test_cape_tradeability.py` to respect the enforced directory cap; its repository root changes to `parents[2]`, and the package initializer is empty. Discovery and both runtime lanes require a new driver run under the revised selectors.
