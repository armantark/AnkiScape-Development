# Jev grill handoff: AnkiScape pipeline (2026-09-22)

## Goal

Decide, in one `grill-me` session, where Jev can make glance checks in AnkiScape pipeline. Write the result as a spec. Nothing is built in this thread.

## Context

Jev is TypeSafe's System One model. It reads a text state and answers typed questions: Choice (one of a set), Noul (probability of yes), and Score (position on a scale). It answers in about 0.2 seconds, costs $0.042 per million input tokens, reads at most 32K tokens of state per call, and keeps no memory between calls.

Read these first:

- `~/fleet/skills/universal/typesafe-ai/SKILL.md`: the ten-second test and the state test decide whether a judgment fits Jev.
- `~/fleet/GLOSSARY.md`: Jev makes a **glance check** (the answer is in the text it gets). It never makes an **audit** (the answer needs evidence outside the text).
- `~/Documents/Claude Code/memory-bank/specs/jev-hooks/`: tickets 03 to 08 hold the fleet calibration data from 2026-09-21 and 2026-09-22.

A Python client already exists at `~/fleet/config/claude/hooks/typesafe_client.py`. The API key is in `~/.local/state/typesafe/client.env` (mode 0600). Do not print or copy the key. Any other client must send its own `User-Agent` header, because Cloudflare answers the default Python agent with 403 "error code: 1010". A `curl ` command inside the state can also trip the firewall ("Attention Required! | Cloudflare").

## Lessons from the fleet calibration (2026-09-22)

Jev did well when the text it received held the whole answer:

- It found a message pasted into the wrong thread: at P(new topic) >= 0.7 it fired on 86 of 200 moved messages and 14 of 200 unmoved ones, and most of the 14 were real topic changes.
- It found an explicit "keep this warm" request with no false grants in 675 messages.

Jev failed when the answer depended on facts outside the text:

- It could not tell from a turn's final text whether the promised work happened. The fleet removed that hook.
- It could not match a report's claim to the command that did it: at 80% recall, 9 of 10 warnings were false.
- It picked the correct model seat for a task 52.6% of the time. Opus 5 picked it 70.3% of the time.
- It predicted whether the owner would leave for an hour barely above chance (AUC 0.58).

Rules that came out of the calibration:

1. Calibrate every threshold on real data from this repo before any code acts on it.
2. Give the labeler (a reasoning model or the owner) exactly the same state that Jev gets. Labels made on less information than the judge had are not evidence.
3. Gate on the probability of the label that code acts on, not on Choice confidence. Confidence measures how concentrated the distribution is.
4. Put a Jev result in front of a slower judge only when Jev can clear the easy cases. Jev alone must not block or delete anything.

## Candidates for AnkiScape pipeline

Jev as a screen in the restoration pipeline, never the verdict. Candidates:

1. Backlog triage: one Choice per row over the seven kanban labels, and one over the canonical statuses. On 2026-09-21 the backlog had 15 distinct status strings over 47 rows.
2. Review finding survival, with the cited slice in the state.
3. Citation drift grading, after the TypeSafe `citation_check` cookbook.

Dropped after the fleet calibration: dispatch routing (Jev picked the correct seat 52.6% of the time) and report screening as a claim-versus-command match (9 of 10 warnings false). Grill on order and on what stays with a reasoning model.
